# Project instructions

## Scope and isolation

- This is an independent, offline-first Python evaluation harness. The approved product name is FixtureDelta Lab.
- Milestones 1A through 3A cover contracts, input validation, synthetic fixtures, pure
  deterministic evaluators, single-run orchestration, baseline/candidate comparison,
  provenance, deterministic quality gates, CLI, deterministic reports, tests, packaging,
  VS Code setup, and a reproducible synthetic end-to-end demo with portfolio docs.
  The owner authorized audit and portfolio-release checkpoints, final rebranding,
  and MIT licensing. Stop after local release preparation. Publication, remote
  creation, tags, external integrations and later features require a separate request.
- Work only in this project. Do not reuse code, cases, or private data from other projects.
- No external LLM requests, paid API calls, telemetry, real personal data, training,
  deployment, or GitHub publication. Do not create a remote repository.
- Keep all environments and editor settings project-local. Never modify global settings.
- Do not bypass Windows restrictions or request sandbox escalation.

## Engineering

- Use Python 3.12+, `src/fixturedelta_lab`, type annotations, and English documentation.
- Prefer the standard library. Justify each dependency; runtime dependencies are currently empty.
- Keep domain contracts independent of file I/O, evaluators, reporting, and CLI concerns.
- Reject invalid, ambiguous, or unknown input fields. Never silently skip missing cases.
- Preserve Unicode, whitespace, and case unless a versioned evaluator explicitly says otherwise.
- Deterministic content checks establish compliance with specified rules, not truth or safety.
- Never invent latency, tokens, cost, model identity, or provenance.
- Released fixture versions are immutable; changed cases require a new dataset version.
- Run `.\scripts\uv.ps1 lock --check --offline`, `.\scripts\uv.ps1 run --locked --offline pytest`,
  `.\scripts\uv.ps1 run --locked --offline ruff check .`, and `.\scripts\uv.ps1 run --locked --offline ruff format --check .`.
- For packaging changes, run `.\scripts\uv.ps1 build --offline` and verify the installed wheel independently.
- Keep `uv.lock` generated by uv, never hand-edit dependency hashes.
- Use `scripts/uv.ps1` on Windows: it checks the project-local tool or first PATH
  executable and rejects versions outside >=0.13.4,<0.14. Do not upgrade global tools.
- Preserve legacy fingerprint namespace strings; the rebrand must not rehash evidence.

## Browser availability

No frontend belongs in Milestone 1A. If future work requires browser validation, check
callable tools before declaring a plugin missing. When `mcp__cua_repl.js` is exposed,
use its documented entry point and the `browser` skill available in the current session.
Actual current-session operation takes precedence over older skills' absence heuristics.
Report installation, current-session availability, and Chrome connection separately.
Do not claim browser access works without verifying it.
